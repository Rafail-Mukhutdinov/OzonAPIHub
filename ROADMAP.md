# 🗺️ План развития OzonAPIHub (2026)

Этот документ содержит стратегию развития проекта, технические цели и идеи по улучшению архитектуры.

---

## 🎯 Ближайшие цели (Q1-Q2 2026)

### 1. Стабильность и Безопасность
- [ ] **Alembic**: Внедрение миграций для управления схемой БД PostgreSQL. Это позволит обновлять базу на сервере без риска потери данных.
- [ ] **Rate Limiting**: Ограничение количества запросов к API для защиты от перегрузок (DDOS) и соблюдения лимитов Ozon API.
- [ ] **Redis**: Кеширование ответов Ozon API. Это ускорит загрузку дашборда в 5-10 раз для часто запрашиваемых периодов.

### 2. Аналитика и Финансы
- [ ] **Dashboard v2**: Расширенные графики прибыльности, включая ROI и маржинальность по каждому SKU.
- [ ] **Интеграция с расходами**: Автоматический вычет себестоимости (COGS) и рекламных расходов из выручки для расчета "чистой" прибыли.
- [ ] **Экспорт данных**: Выгрузка отчетов в Excel и PDF для бухгалтерии.

### 3. Масштабируемость и фоновая обработка
- [ ] **Параллельная обработка (Worker-ы)**: 
  - Переход на распределенную очередь задач (**Celery** или **ARQ**) на базе Redis.
  - Распараллеливание синхронизации пользователей между несколькими воркерами (10+ потоков).
- [ ] **Умный интервал (Adaptive Polling)**:
  - Реализация алгоритма адаптивного изменения частоты опроса Ozon API.
  - Динамический интервал: от 1 до 10 минут в зависимости от активности продаж магазина.
- [ ] **Использование Webhooks Ozon**:
  - Реализация приема уведомлений (Push) от Ozon API о новых заказах и изменениях статусов.
  - Переход к событийной модели обновления данных для снижения нагрузки на сервер.

## 🛠️ Технические рекомендации (Техдолг)

### Оптимизация БД
- **Batch Operations**: Текущее обогащение данных идет по одному заказу. Необходимо переписать сервис на массовые (bulk) вставки, что сократит количество запросов к БД в десятки раз.
- **Индексы**: Добавить составные индексы в PostgreSQL на поля `user_id` + `created_at` для мгновенной фильтрации в больших исторических массивах.

### Мониторинг
- **Sentry**: Интеграция для мгновенного получения уведомлений об ошибках у пользователей.
- **Логи в ELK**: Переход на структурированный JSON-формат логов для удобного поиска через Kibana или Loki.

### Инфраструктура
- **CI/CD**: Настройка автоматического тестирования и деплоя на сервер при пуше в ветку `main`.
- **Healthchecks**: Добавление проверок состояния базы и API в Docker Compose.
