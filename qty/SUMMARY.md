📋 ПРОБЛЕМА
-----------
В приложении OzonAPIHub данные по выручке и количеству товаров за конкретные 
дни (10 и 15 июня) не совпадали с данными в Личном Кабинете Ozon.

Примеры расхождений:
  • За 15 июня: В ЛК Озона одни значения, в app — 56 шт и 13 213 ₽
  • За 10 июня: Заказ со временем 09.06 22:24 UTC должен попадать в отчет за 10-е
  • Отмены: Заказ 08494044-0542-1 со статусом "Отменён" неправильно обрабатывался


🔍 НАЙДЕНО: 5 КРИТИЧЕСКИХ ОШИБОК
---------------------------------

1️⃣  ОШИБКА: String сравнение дат вместо ISO
    Файл: routes/analytics.py
    Локация: _get_unified_postings()
    Проблема: "2026-06-14" (дата) >= "2026-06-15T10:30:45Z" (ISO) - неправильное сравнение
    Статус: ✅ ИСПРАВЛЕНО

2️⃣  ОШИБКА: Неправильное расширение окна поиска
    Файл: routes/analytics.py
    Локация: daily_stats(), sales_report_universal()
    Проблема: timedelta(hours=14) вместо timedelta(hours=3-4)
             UTC-MSK = 3 часа, расширение = 28 часов (неоптимально!)
    Статус: ✅ ИСПРАВЛЕНО

3️⃣  ОШИБКА: Отсутствует db.commit()
    Файл: services/enrichment.py
    Локация: enrich_posting_from_ozon() - конец функции
    Проблема: OrderProduct добавляются в db.add(), но не коммитятся
             Товары не сохраняются в БД!
    Статус: ✅ ИСПРАВЛЕНО

4️⃣  ОШИБКА: Использование двух источников (Order + OrderPosting)
    Файл: routes/analytics.py
    Локация: _get_unified_postings()
    Проблема: Объединение сырых Order и нормализованных OrderPosting
             Может привести к дублированию или потере данных
             Товары OrderProduct связаны только с OrderPosting!
    Статус: ✅ ИСПРАВЛЕНО

5️⃣  ОШИБКА: Неполная фильтрация статусов отмен
    Файл: routes/analytics.py
    Локация: is_cancelled()
    Проблема: Case-sensitive проверка, возможны пропуски
             ("Cancelled" vs "cancelled" vs "CANCEL")
    Статус: ✅ ИСПРАВЛЕНО


✅ ИСПРАВЛЕНИЯ
--------------

1. ИСПРАВЛЕНИЕ #1: ISO сравнение дат
   Было:  db_search_since = since_dt.strftime("%Y-%m-%d")  # "2026-06-14"
   Стало: db_search_since = (since_dt - timedelta(hours=4)).isoformat()  # ISO с временем
   Эффект: Правильная фильтрация по датам

2. ИСПРАВЛЕНИЕ #2: Оптимальное расширение окна
   Было:  timedelta(hours=14)
   Стало: timedelta(hours=4)  # 3 часа (UTC-MSK) + 1 час запас
   Эффект: Точная выборка, оптимизация запросов

3. ИСПРАВЛЕНИЕ #3: Добавлен db.commit()
   Было:  db.add(obj)
          return {"status": "ok"}
   Стало: db.add(obj)
          db.commit()
          return {"status": "ok"}
   Эффект: Товары сохраняются в БД

4. ИСПРАВЛЕНИЕ #4: Использование только OrderPosting
   Было:  raw_orders = db.query(Order)...
          norm_orders = db.query(OrderPosting)...
          # Объединение обоих источников
   Стало: norm_orders = db.query(OrderPosting)...
          # Только нормализованные данные
   Эффект: Нет дублирования, гарантированная связь с товарами

5. ИСПРАВЛЕНИЕ #5: Надежная фильтрация отмен
   Было:  is_cancelled = "cancelled" in status.lower()
   Стало: cancelled_patterns = ["cancelled", "отменен", "отменён", "cancel"]
          is_cancelled = any(p in status_lower for p in cancelled_patterns)
   Эффект: Надежная обработка всех форматов статусов
